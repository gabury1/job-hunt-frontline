## 팀이 하는 일

원문에 팀 · 회사 소개 문장은 없다. 업무 설명으로 보면, 팀카이는 Agent Engineer가 만든 프레임워크와 제품 기능을 바탕으로 고객사마다 CS 응대 에이전트를 구축하고, 고객사와 합의한 AI 응대율 · AI 업무 처리율에 도달할 때까지 운영한다. FDE는 PM · Agent Engineer와 함께 한 고객사에서 발견된 페인이 다음 고객사 빌드에서 자동으로 사라지는 상태를 만든다.

## 담당할 업무

| 업무 | 기술 |
|---|---|
| 고객사 에이전트 빌드: 담당 고객사의 도메인 · 시스템 · 정책에 맞는 에이전트 1 instance를 구축한다. 외부 API 연동, 정책 인용, intent 분류, supervision · 가드레일 설정, 사람 상담사 핸드오프 정책까지 Agent PM과 합의된 사양 그대로 코드와 설정으로 옮긴다 | 외부 API |
| 고객사 현장 출장: 첫 진입 때 며칠간 그 회사의 CS 운영을 옆에서 관찰하며 문의 유형 · 정책 · 예외 케이스 · 톤을 흡수한다. 운영 단계에서도 큰 정책 변경이나 어려운 케이스가 생기면 현장에서 운영팀과 함께 해결한다 | |
| 운영과 튜닝: 출시 후 실제 대화 로그를 매일 보며 실패 케이스를 태깅하고 원인을 진단한다. Agent PM과 짝을 이뤄 어떤 개선이 어떤 KPI를 움직일지 가설을 세우고 다음 이터레이션에서 검증한다. 합의한 AI 응대율 · AI 업무 처리율에 도달할 때까지 운영에 머문다 | |
| 프레임워크 인사이트: 현재 프레임워크로 풀리지 않는 케이스, 자주 막히는 패턴, 도메인 모호성을 PM · Agent Engineer · FDE 3자 정기 회의에서 공유하고, 다음 모든 고객사에서 자동으로 풀려야 할 부분을 Agent Engineer에게 신호로 넘긴다 | |

회사 기술스택은 TypeScript, Kotlin, NextJS, ReactJS, ExpressJS, Spring, MySQL 이다.

## 지원 자격

### 필수 경험과 역량

- LLM 기반 제품을 직접 빌드해 본 경험, 또는 빌드를 배워 가며 6개월 안에 1개 고객사 instance를 출시할 수 있다는 자기 확신과 학습력
- 외부 API를 직접 연동해 단순 응답을 넘어 실제 작업을 수행하는 에이전트를 구현해 본 코딩 역량(혹은 그에 준하는 실무 코딩 경험)
- 새로운 도메인을 빠르게 흡수하는 학습력, 고객사 현장에 며칠 들어가 운영팀의 일을 보고 핵심 패턴을 뽑아내는 관찰력
- 실제 대화 로그 · 운영 데이터를 매일 들여다보고 실패 케이스에서 원인을 찾아 가설로 옮기는 분석력
- 고객사 실무 담당자 · 운영팀과 직접 대화하며 합의를 만드는 커뮤니케이션 역량, 출장과 현장 협업에 거부감 없음
