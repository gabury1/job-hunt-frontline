- NaviCore 3.x → 4 비호환 전환이 진행 중이다. 기존 현장 이전 작업이 개발 · 현장 인력에 부담이 될 수 있다 (추정)
- 공고 담당업무에 「고객 현장 배포 후 장애 분석 · 대응」이 있다. 현장 대응 · 출장 부담이 따른다
- 구조조정 · 소송 · 규제 이슈: 못 찾음
- 리뷰에서 반복되는 불만: 공개 리뷰가 없어 확인 못 함

기술 스택 (공고 · 제품 페이지 기준)

- 코어 언어: C++ (Modern C++17/20 우대)
- 로봇 미들웨어: ROS 2 Humble (NaviCore 4)
- 스크립트 · 테스트 · 시뮬레이션 도구: Python · TypeScript 등 본인이 편한 언어
- 통신 · 표준: VDA5050 · MQTT · OPC UA · Modbus TCP · PLC 직접 통신
- 라이브러리: Boost · Poco (우대)
- 테스트: Google Test/Mock (우대)
- 저장소: Redis · SQLite · 시계열 DB (우대)
- 인프라: Docker · CI/CD (우대). 관제 서버는 Active-Standby 이중화 + Auto Recovery
- 시뮬레이터: Navi-Core Sim · PLC-Sim · 배속 시뮬레이션, Isaac Sim · Gazebo (우대)
- 알고리즘: MAPF (CBS 실용화) · ETA 기반 교착 사전 차단 · 구역별 분산 ACS (500대+ 설계)

일하는 방식 (공고 원문)

- 「설계와 코드는 동료와 함께 리뷰」한다고 적혀 있다
- 「AI 를 적극적으로 쓴다. 코드 작성 · 리뷰 · 로그 분석 · 문서화까지 AI 와 함께」가 기본이다
- 자격요건에 「AI 가 만든 결과를 그대로 믿지 않고 직접 확인하는 분」이 있다
- 현장 투입 전에 시뮬레이션과 테스트 코드로 먼저 검증한다
- 기능 요구사항(FR) 문서화와 설계 리뷰를 한다

- 품질 범위: 단위 테스트 · 리팩토링 · 성능 최적화(I/O · 메모리 · 지연시간)
- 운영 범위: 현장 배포 후 로그로 장애 원인을 찾고 재발을 막는다
- 대외 범위: 프로토콜 연동 관련 고객사 기술 커뮤니케이션 지원
