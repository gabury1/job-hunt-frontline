- 재무 공시가 없다. 흑자 전환은 회사 주장뿐이고 금액 · 자본잠식 여부를 확인할 수 없다

**기술 스택** (공고 · 인터뷰)

- 백엔드: Java · Spring · JPA · Hibernate · Querydsl
- 데이터: MySQL · MongoDB · Redis · Elasticsearch (건물 검색용 자체 검색엔진 도입, FE 유민우 인터뷰)
- 파이프라인 · 인프라: Airflow · IaC(테라폼) · AWS · CDN · 오토스케일링
- 모니터링: Grafana · Slack 알림 연동 · 우대사항에 Sentry · Datadog
- 프론트엔드: Next.js (Pages Router)
- AI 도구: Codex (퇴근 전 프롬프트를 남겨 밤사이 개발)

**일하는 방식에서 드러난 것**

- 매주 개발팀이 아키텍처와 DB 구조를 함께 점검한다 (BE 인터뷰)
- 개발팀 리드가 설계를 아키텍처 관점에서 리뷰한다 (BE 인터뷰)
- 단순 반복 이슈는 모니터링 도구와 AI 로 코드 수정 · PR 생성까지 자동으로 이어지게 했다 (BE 인터뷰)
- 배포 전 CI 단계 검증을 강화하고, 배포 뒤 오류를 추적해 대응이 필요한 것만 분류한다 (FE 인터뷰)
- 프론트 팀은 평소 하루 5회 이상, 많을 때 20회 가까이 배포한다 (FE 인터뷰)
- 배포 직후 성능 저하를 막으려고 배포 과정에서 JVM 웜업을 넣었다 (BE 인터뷰)
- 건물 상세 페이지 응답 시간을 캐시 · DB 구조 · 라이브러리 분석으로 약 6배 개선했다 (BE 인터뷰)
- 코드 리뷰 방식: 못 찾음
