## 업무 방식 · R&R

**팀 구성**

- 목적 조직(스쿼드)과 직무 조직(그룹)이 겹치는 구조다. 「팀, 스쿼드, 그룹 단위로 목표 관리」 (팀 소개 페이지).
- 확인된 스쿼드: 액티베이션 스쿼드 (PO Smith, 「가입 7일 안에 운동 3회」가 목표, Smith 인터뷰).
- 확인된 그룹: 개발그룹 (River 리드) · Solver Group (팀 소개 페이지).
- PO 2명 · 프로덕트 디자인 리드 1명이 있다. 기획을 PO 가 맡는다.

**신입이 맡게 될 일** (공고 기준)

- Python · Django · DRF 로 플랜핏 API 서버 개발
- 조직에 따라 GPT API · 자체 모델 개발이나 Kotlin · Spring Boot CRM 서버 개발
- 급성장에서 생기는 기술 문제 해결
- 유저 데이터를 근거로 기능 기획 · 개선에 참여

**일하는 방식**

- 주 단위 스프린트다. 목요일 문제 발굴 → 금요일 문제 정의 → 월요일 해법 찾기 순서로 돈다 (Smith 인터뷰).
- 의사결정은 자율형이다. 「직급과 연차보다 유저 문제 기준」 · 「누구나 제품 기획에 참여」 (팀 소개 페이지).
- 주 10~20개 실험으로 검증한다 (팀 소개 페이지).
- 협업 도구는 Slack 이 확인된다 (블로그 「Slack으로 보는 팀원들」).
- 매월 All Hands 에서 매출 지표 · 목표 달성 현황을 공유한다 (팀 소개 페이지).
- 출근 근무다. 오전 9~10시 유연 출근 (공고). 재택 언급은 못 찾음.
- 온콜 · 운영 부담은 못 찾음. 백엔드가 2명이라 운영 대응을 나눠 질 인원은 적다.
