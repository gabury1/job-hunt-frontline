## 업무 방식 · R&R

### 팀 구성

- 스쿼드(목적 조직) + 챕터(직무 조직) 매트릭스 — 예: "Scholar Division 과 Frontend Chapter", "Like Studio 를 만드는 스쿼드"(기술 블로그).
- 디비전: Scholar Division · AX 디비전(B2B, 2026-08 신설).
- 데이터 그룹 7 명.
- 스쿼드마다 PM 이 있다(데이터 플랫폼 글 "다른 스쿼드 PM 들과 협업").

### 열린 개발 공고와 신입 가능성

| 공고 | 요구 경력 | 신입 가능성 |
|---|---|---|
| AI Engineer(전문연구요원 가능) | 채용 페이지 「무관」 · 직행 「1년 이상」 | 가장 현실적. 단 상용 LLM 기능 배포 경험 요구 |

| Mobile Engineer (React Native) | 경력 | 직무 다름 |

- 채용 FAQ: 공고의 경력 조건을 못 맞춰도 그에 준하는 경험이면 지원 가능.
- 산업기능요원 · 전문연구요원은 엔지니어 포지션 전부 가능(FAQ).

### 신입이 맡게 될 일(AI Engineer 공고 기준)

- 문제 정의부터 에이전트 · 프롬프트 · 도구 설계, 평가, 프론트/백엔드 연결, 배포 · 운영까지 기능 하나를 끝까지 맡는다.
- 평가셋 · LLM 판정으로 변경 전후를 비교하고 A/B 테스트로 효과를 검증한다.
- 품질 · 속도 · 비용을 따져 모델 조합 · 서브에이전트 · 캐시를 설계한다.
- 실패 사례 분석과 모니터링 운영 체계를 맡는다 — 운영 부담이 직무 안에 들어 있다.

### 참고: 백엔드(Platform) 공고가 말하는 백엔드 일

- 자체 실험 플랫폼 · 메시징/딜리버리 · 데이터 파이프라인 운영과 개선.
- "어떤 유저에게 무엇을 보여줄까" 결정 규칙을 한 곳에 선언하고 실행 이력을 추적하는 구조.
- 우대: 결제 · 구독, 메시지 큐 기반 이벤트 처리, DDD/헥사고날.

### 일하는 방식

- 출근 근무. 오전 9~11시 자율 출퇴근.
- 원격 · 재택: 공고에 언급 없음.
- 직급 없이 닉네임으로 소통.
- 역할 경계가 유연하다 — 프론트엔드가 광고 성과 문제를 풀고, ML 엔지니어가 FE 까지 만든 사례가 블로그에 있다.
- 협업 도구: Slack · Notion(데이터 플랫폼 글에 "슬랙과 노션 곳곳에 공유").
- 온콜: 명시된 것 못 찾음. AI Engineer · 백엔드 공고 모두 "운영"을 직무에 넣었다.
- 채용 원칙 False Positive Zero — 맞지 않는 사람을 뽑는 오류를 0 으로(블로그).
