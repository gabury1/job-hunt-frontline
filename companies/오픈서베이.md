## 리스크

- **적자 전환**: 2025년 영업손실 7.6억 원. 2023년 적자 → 2024년 흑자 → 2025년 적자로 오간다.
- **얇은 자본**: 자본총계 5.1억 원. 자본금 1.5억 원보다 커서 자본잠식은 아니다.
- **결손금**: 미처리결손금 47.0억 원(2025년 말).
- **부채**: 부채총계 69.9억 원이 모두 유동부채다. 자본 대비 약 14배.
- **단기차입금**: 29억 원(2024 · 2025 같음).
- **현금**: 현금성자산 23.8억 + 단기금융상품 10억 원(2025년 말).
- **구조조정 · 소송 · 규제**: 못 찾음.
- **리뷰에서 반복되는 불만**: 워라밸(항목 평점 3.0으로 가장 낮음), 업무량, 퇴사가 많다는 말.
- **최근 리뷰 분위기 악화**: 2026년 5월 이후 리뷰 넷 중 셋이 평점 1~2점이다. 「인력을 더 이상 뽑지 않음」(2026-10)이라는 리뷰와 달리 백엔드 공고는 열려 있다.

**일하는 방식 (엔지니어링 페이지)**

- 2주 스프린트 안에 문서 · 개발 · QA · 배포를 끝낸다.
- 일 하나가 PRD → RFC → Design → Spec → Plan → Impact 문서 여섯 개를 거친다.
- 문서 초안과 코드 구현은 AI Agent가 쓰고 PR을 올린다. 사람은 단계마다 리뷰하고 승인한다.
- 되돌리기 어려운 결정은 ADR로 남긴다.
- 기본 브랜치 머지 · 운영 배포 · DB 변경은 사람만 한다.
- 인터페이스 · 데이터 계약 · 인증 경계를 바꾸는 설계는 사람이 승인한다.
- 배포 뒤 지표를 목표와 비교해 회고한다. 목표에 못 미친 지표도 그대로 적는다.
- 공개한 성과: 조회 중앙값 약 19초 → 66ms(2일 작업).
- 공개한 성과: Java 파일 327개를 스프린트 5개에 걸쳐 Kotlin으로 전환. 계약 테스트가 배포 전 결함 2건을 잡음.
- 공개한 성과: 스트림 처리 중복률 47% → 0.1%.

## 업무 방식 · R&R

**팀 구성**

- 제품 넷(오베이 · 데이터스페이스 · 합성패널 · 컨셉 스튜디오)을 만든다. 팀이 제품별인지 직무별인지는 못 찾음.
- 공고 기준 백엔드는 두 갈래 일을 한다: 합성패널 분석 시스템(분석 API · 데이터 파이프라인), AI Agent 실행 환경(도구 호출 · 분석 작업 연결).
- PM 유무: 못 찾음. 문서 단계에 PRD가 있어 기획 문서는 있다.

**신입이 맡을 일 (공고)**

- 처음에는 기존 시스템과 업무 흐름을 익히고 범위가 명확한 일부터 맡는다.
- 이후 요구사항 구체화부터 설계 · 구현 · 운영까지 한 업무를 끝까지 맡는다.
- 맡은 제품 영역의 백엔드 기능 설계 · 개발.
- 반복 처리 자동화와 데이터 파이프라인 설계 · 운영.
- API · 데이터 스키마 설계와 기존 구조 개선.
- 운영 문제를 로그와 지표로 추적하고 재발 방지.

**개발자의 역할 (엔지니어링 페이지)**

- 코드를 치는 시간보다 판단하는 시간이 길다고 밝힌다.
- 문제를 RFC 한 페이지로 정의하고 Agent가 조사한 선택지 중 설계를 고른다.
- Agent의 역할 · 리뷰 게이트 · 상한을 정하는 「Harness」를 설계한다.
- 합성패널이 실제와 같은지 재는 평가 기준을 설계한다.
- 배포를 승인하고 책임진다.
